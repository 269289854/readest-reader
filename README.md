# Readest Reader

`readest-reader` is the Reader-only, embeddable boundary extracted from [Readest](https://github.com/hehetoshang/readest). It contains the React/Next.js reading surface, the `foliate-js` engine and the `readestlib` Tauri backend used by [Moke](https://github.com/269289854/moke-miku).

The migration baseline is Readest commit `b2b5d2f16ae5c76f8b71fec55ba1eef9713cf195`. The Reader-relevant follow-up from merged [Readest PR #33](https://github.com/hehetoshang/readest/pull/33), commit `cf41c5ae5682ac6a85dcd3fb77eb7911ce8ab300`, is synchronized on top. The original Readest repository and its history are not modified. The retained history in this repository covers the Moke/Reader first-parent changes; import commits record the path-filtered snapshots.

## Boundary

Included:

- the `/readest/reader` page and its reachable Reader UI/domain modules;
- EPUB, PDF, MOBI/AZW, FB2, CBZ, TXT and Markdown rendering dependencies;
- annotations, navigation, dictionaries, fonts, themes, TTS, translation and optional AI panels used by Reader;
- the embeddable Rust crate at `apps/readest-app/src-tauri`;
- pinned `foliate-js`, `simplecc-wasm` and `js-mdict` submodules;
- Moke launch/progress/event integration and contract tests.

Excluded:

- the Readest library, authentication and account application surfaces;
- Readest server/API routes, billing, deployment workers and Docker images;
- browser, Calibre, KOReader and Windows thumbnail extensions;
- release/store metadata and unrelated platform packaging automation.

This is an embedded component, not a second ebook server. `mokeServerUrl` is the Talebook server selected in Moke; Reader itself is served from Moke's bundled static assets.

## Requirements

- Node.js 20.9 or newer
- pnpm 11.1.1 (Corepack recommended)
- Git with submodule support
- Rust 1.88 or newer for `readestlib` checks

## Fresh clone

```bash
git clone --recursive https://github.com/269289854/readest-reader.git
cd readest-reader
corepack enable
pnpm install --frozen-lockfile
pnpm setup:vendors
pnpm typecheck
pnpm test
pnpm build
pnpm start
```

Open `http://127.0.0.1:3001/readest/reader`. A browser can verify the static shell; opening a host-authorized local file requires a Tauri host implementing the contract below.

For development with hot reload:

```bash
pnpm dev
# http://127.0.0.1:3001/readest/reader
```

Rust boundary check:

```bash
pnpm check:rust
```

## Build output

`pnpm build` emits only the Reader page to `out/readest`. No Readest library/account/API route is exported. Moke copies or bundles this directory under its own `out/readest` path.

Vendor assets under `apps/readest-app/public/vendor` are generated by `pnpm setup:vendors` (and automatically before `pnpm build`) and intentionally not committed:

- PDF.js from `vendor/foliate-js`
- SimpleCC WASM from `vendor/simplecc-wasm`
- Jieba WASM from the pinned npm dependency

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_APP_PLATFORM` | `tauri` | Selects the native Reader service implementation. |
| `NEXT_PUBLIC_READEST_PROFILE` | `moke-reader` | Documents the Reader-only build profile. |
| `NEXT_PUBLIC_EMBEDDED_BASE_PATH` | `/readest` | Static URL prefix expected by Moke. |
| `READEST_READER_HOST` | `127.0.0.1` | Host used by `pnpm start`. |
| `READEST_READER_PORT` | `3001` | Port used by `pnpm start`. |
| `READEST_READER_DIST` | `out` | Static output root used by `pnpm start`. |

No credential is required to build Reader. Put developer-specific values only in ignored `.env*.local` files; never commit Talebook passwords, cookies, tokens or signing material.

## Moke contract

The machine-readable contract is `contract/moke-reader.v1.json`; the detailed protocol is in `docs/MOKE_CONTRACT.md`.

At a high level:

1. Moke serves the build at `/readest` and opens `/readest/reader`.
2. Desktop passes the approved local file through `window.OPEN_WITH_FILES`; single-WebView mobile targets pass repeated `file` query parameters.
3. Moke passes optional book/progress context through `mokeBookId`, `mokeServerUrl` and `mokeRestoreProgress`.
4. Reader emits lifecycle/progress/error events through `ext_reader_event`.
5. On single-WebView targets Reader saves progress directly to the selected Talebook server with Tauri HTTP, `credentials: include`, and the host cookie jar.

Moke must register `readestlib` plugins, protocols and invoke handlers, and must list Reader plugin crates as direct Cargo dependencies so Tauri can discover their ACL manifests.

## Compatibility

| readest-reader | Source baseline | Moke |
| --- | --- | --- |
| `0.1.x` | `b2b5d2f16ae5c76f8b71fec55ba1eef9713cf195` + Reader follow-up `cf41c5ae5682ac6a85dcd3fb77eb7911ce8ab300` | Moke `1.1.3+` using contract `moke.readest.embed.v1` |

Behavior intentionally unavailable in this repository: Readest library/account pages, cloud-library administration, billing, server-side API routes and standalone Readest release packaging. Reader features that depend on an external provider still require configuration supplied by the embedding application.

## Updating from Readest

1. Record the upstream/fork commit in the pull request and update the compatibility table.
2. Produce a path-limited diff for the modules reachable from `src/pages/reader.moke.tsx`, the native Reader API and pinned vendor revisions.
3. Port changes on a topic branch; do not rewrite either repository's published history.
4. Run `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm check:rust`, then the real Moke E2E in `docs/E2E.md`.
5. Update `contract/moke-reader.v1.json` only for backward-compatible additions. Breaking changes require a new contract ID/version and coordinated Moke PR.
